# Pilot evidence audit (Milestone 1): 13 November 2026

**Work done during the sprint (13 Nov 2026), on branch `sprint/m1-pilot-evidence`.** This audit
covers citation evidence only. **No model has been run, and no experimental results exist.**
The frozen design in `PROTOCOL.md` is unchanged. Preexisting work is listed in
`PRE_SPRINT_DISCLOSURE.md`.

Machine-readable records:
- `data/benchmark.json`, per condition: `provenance.evidence_record` (A/B) and `provenance.fabrication_review` (C).
  Every value this audit overwrote is kept in `provenance.m1_previous_values`.
- `data/pilot_manifest_m1.json`: the eligibility manifest, generated by `src/audit_dataset.py --manifest-out`.
- `data/evidence/m1_source_fetch_log.json`: every URL fetched, with HTTP status, including failures.
- `data/evidence/m1_catalog_queries.json`: raw Crossref, OpenAlex and Semantic Scholar responses.

**Who did the review:** an AI agent (Claude Code), helped by scripts. It fetched each page and searched
the page text for each quoted sentence. A script then confirmed that every `verbatim_quote` in the
benchmark appears in the fetched page text. **No human has reviewed these records yet. The PI must
spot-check every eligible item before any confirmatory use.**

## 3. Fabricated-C searches (13 Nov 2026)

Each pilot C was searched through these channels:
- **Web search:** exact-phrase queries on the institution, the title, and (for P01) the report ID.
  The exact strings are recorded per item in `fabrication_review.searches`.
- **Crossref** `query.bibliographic`: the top 5 results were checked for an exact title match.
- **OpenAlex** works `title.search` phrase filter.
- **OpenAlex** institutions search.
- **Semantic Scholar:** attempted, but **every query failed with HTTP 429** (rate limiting). It is recorded as not completed and not counted.

**Outcome: no exact institution or title match on any completed channel for any of the 8 items.**
OpenAlex returned 0 results for every title phrase and every institution, apart from the discarded
candidate noted below.

**This is a negative search, not proof of nonexistence.** Grey literature, non-indexed catalogues
and non-English sources were not searched. C is marked `verified` with `verification_scope =
documented_negative_search`, which matches the PROTOCOL §4 standard ("verified as nonexistent via
available search"). The validator accepts C only when at least 3 distinct channels completed **on
the exact citation text currently displayed**. If C's text changes later, its search log no longer
counts until the searches are re-run.

The 12 non-pilot C references were not re-searched and remain `unverified`.

### Unresolved confounds (not fixable without changing the protocol)
1. **Institutional familiarity.** Every B names a real, well-known body (NASA, NOAA, NIH, NIST,
   RSC, ABS). Every C names an invented body. The B-vs-C contrast therefore varies existence
   *and* familiarity together, so this is a limitation to report.
2. **Length asymmetry.** C is longer than B in 7 of 8 items. P07 (+34) and S03 (+30) are within the
   ±40 threshold but far from equal.
3. **B subtype mix.** The pilot has P03 = contradicts and 7 × related_only. The two subtypes must be analysed separately.
4. **Same-source A/B in P03.**
5. **Archive-only evidence for P05 (A and B) and S01 (A).** The live pages were unreachable by automated clients on 13 Nov.
6. **Small n.** 5 primary and 3 seeded-secondary items allow pilot checks only, not inference.

## 5. Validator and audit changes

`src/validate_dataset.py` and `src/audit_dataset.py` were changed during the sprint:
- A `verified` status counts only when an evidence record backs it. The record must contain the
  date, the method (live fetch or Wayback snapshot), the URL, an archive URL for archived evidence,
  and `claim_checked`, which must equal the attached claim. For A it also needs a verbatim quote.
  For B it needs a quote or an absence check, plus a subtype that agrees with the recorded relationship.
- A B source that supports its attached claim is never accepted. If it is still marked `verified`, that is a **structural error**.
- C requires the multi-channel search log described in §3. An exact-match hit blocks C, and is a structural error if C is still marked `verified`.
- The audit reports two counts: status-flag counts and evidence-backed counts.
  `--manifest-out` writes `data/pilot_manifest_m1.json`.
